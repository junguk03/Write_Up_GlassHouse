# CTF 규칙

문제를 만들 때와 풀 때 지킬 약속입니다. 규칙이 생기면 이 파일에 한 줄씩 더합니다.
만드는 방법과 교환 절차는 [CTF 문제 제작 · 교환 절차](CTF_WORKFLOW.md)를 보십시오.

---

## 1. 출제 규칙

### 1-1. 원본 `app/` 은 수정하지 않습니다

문제는 항상 `app/` 을 복사한 사본에서 만듭니다.
`app/` 은 취약점이 없는 기준 코드입니다.

### 1-2. 플래그는 `.env` 에만 둡니다

코드, 템플릿, README, 커밋 메시지 어디에도 플래그 문자열을 직접 쓰지 않습니다.
`.env` 는 깃에 올라가지 않으므로 출제 조 서버에만 존재합니다.

커밋하기 전에 `git status` 로 `.env` 가 목록에 없는지 확인합니다.

### 1-3. 플래그와 변수 이름은 문제마다 다르게 합니다

| 항목 | 예 |
|---|---|
| 변수 이름 | `FLAG_E01_IDOR`, `FLAG_E02_PORTAL` |
| 플래그 값 | 다른 문제와 같은 값을 재사용하지 않습니다 |

같으면 한 문제의 플래그로 다른 문제까지 풀린 것처럼 보입니다.

### 1-4. 알면 바로 뚫리는 값도 `.env` 로 뺍니다

소스가 전부 공개되므로, 코드에 적힌 값은 푸는 조도 다 볼 수 있습니다.
아래 값은 코드에 직접 쓰지 않고 `.env` 에서 읽습니다.

| 값 | 코드에 있으면 |
|---|---|
| 관리자 비밀번호 | 그대로 로그인됩니다 |
| `SECRET_KEY` | 세션 쿠키를 위조해 아무 계정으로 들어갈 수 있습니다 |

지원자 계정처럼 **문제 설명에서 공개하는 계정**은 코드에 있어도 됩니다.

### 1-5. 문제 설명에 취약점 이름을 쓰지 않습니다

README 의 제목과 설명에 쓰지 않습니다. 폴더 이름에만 들어갑니다.

### 1-6. `solution/` 은 상대 조가 다 푼 뒤에 올립니다

## 2. 풀이 규칙

### 2-1. 원본 `app/` 과 diff 로 비교하지 않습니다

`diff`, IDE 의 파일 비교 기능, `git diff` 로 원본과 문제 폴더를 맞대어 보면
바뀐 줄이 곧 답이 됩니다. 코드를 직접 읽고 찾습니다.

### 2-2. 공격은 출제 조 서버로 보냅니다

진짜 플래그는 출제 조의 `.env` 에만 있습니다.

| 하는 일 | 대상 |
|---|---|
| 소스 읽기, 로컬 실행 | 내 노트북의 문제 폴더 |
| 공격, 플래그 획득 | 출제 조 주소 `http://<출제조IP>:8000` |

로컬에서 띄우면 더미 플래그만 나옵니다.

### 2-3. AI 는 공부 도구로만 씁니다

| 허용 | 금지 |
|---|---|
| 개념 설명 (예: "IDOR 가 뭐야") | 문제 소스를 통째로 넣고 취약점이나 풀이를 묻기 |
| 내가 고른 코드 일부의 동작 설명 | AI 가 찾아 준 답을 그대로 따라 하기 |
| 익스플로잇 작성 도움 (요청 보내는 법, 문법) | |

취약점을 찾는 것은 사람이 합니다.
AI 에게는 "이 코드가 무엇을 하는지" 까지만 묻고 "어디가 뚫리는지" 는 묻지 않습니다.

### 2-4. 힌트는 한 단계씩 엽니다

막혔을 때 출제 조에게 요청합니다.

1. 취약점 분류 (예: "접근 제어 쪽입니다")
2. 취약한 화면 (예: "내 원서 조회")
3. 취약한 파일
