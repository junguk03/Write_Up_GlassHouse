# CTF 규칙

문제를 만들 때 지킬 약속(1장)과 대회 참가자에게 공지할 규칙(2장)입니다. 규칙이 생기면 이 파일에 한 줄씩 더합니다.
만드는 방법과 교환 절차는 [CTF 문제 제작 · 교환 절차](CTF_WORKFLOW.md)를 보십시오.

---

## 1. 출제 규칙

### 1-1. 원본 `app/` 은 수정하지 않습니다

문제는 항상 `app/` 을 복사한 사본에서 만듭니다.
`app/` 은 취약점이 없는 기준 코드입니다.

### 1-2. 플래그는 `.env` 에만 둡니다

코드, 템플릿, README, 커밋 메시지 어디에도 플래그 문자열을 직접 쓰지 않습니다.
`.env` 는 깃에 올라가지 않으므로 대회 서버에만 존재합니다. 서버 담당자에게 따로 전달합니다.

커밋하기 전에 `git status` 로 `.env` 가 목록에 없는지 확인합니다.

### 1-3. 플래그와 변수 이름은 문제마다 다르게 합니다

| 항목 | 예 |
|---|---|
| 변수 이름 | `FLAG_E01_IDOR`, `FLAG_E02_PORTAL` |
| 플래그 값 | 다른 문제와 같은 값을 재사용하지 않습니다 |

같으면 한 문제의 플래그로 다른 문제까지 풀린 것처럼 보입니다.

### 1-4. 알면 바로 뚫리는 값도 `.env` 로 뺍니다

소스가 전부 공개되므로, 코드에 적힌 값은 푸는 조도 다 볼 수 있습니다.
아래 값은 코드에 직접 쓰지 않고 `.env` 에서 읽습니다.

| 값 | 코드에 있으면 |
|---|---|
| 관리자 비밀번호 | 그대로 로그인됩니다 |
| `SECRET_KEY` | 세션 쿠키를 위조해 아무 계정으로 들어갈 수 있습니다 |

지원자 계정처럼 **문제 설명에서 공개하는 계정**은 코드에 있어도 됩니다.

### 1-5. 문제 설명에 취약점 이름을 쓰지 않습니다

README 의 제목과 설명에 쓰지 않습니다. 폴더 이름에만 들어갑니다.

### 1-6. `solution/` 은 대회가 끝난 뒤에 올립니다

`solution/` 은 `.gitignore` 에 들어 있어 로컬에만 있습니다. 대회가 끝나면 그 줄을 지우고 올립니다.

### 1-7. 포트와 쿠키 이름은 문제마다 다르게 합니다

모든 문제를 한 서버에 띄웁니다. 포트 목록은 [CTF_WORKFLOW](CTF_WORKFLOW.md)에 있습니다.
쿠키는 포트를 구분하지 않으므로 `SESSION_COOKIE_NAME` 을 `gh_<포트>` 로 둡니다. `debug=True` 는 쓰지 않습니다.

## 2. 참가 규칙

대회 당일 참가자에게 공지하는 규칙입니다.

### 2-1. 접속과 제출

| 항목 | 내용 |
|---|---|
| 문제 서버 | `http://<서버IP>:<문제 포트>` (포트는 문제 설명에 있습니다) |
| 플래그 형식 | `GlassHouse{...}` |
| 제출 | CTFd 에 제출합니다. 제출 횟수 제한은 없지만 무작위 대입은 금지입니다 |

### 2-2. 공격 범위

| 허용 | 금지 |
|---|---|
| 문제 설명에 적힌 포트의 웹 서비스 | CTFd(8000 포트)와 서버 자체 공격 |
| Burp Suite, curl, 직접 짠 스크립트 | 서버를 멈추게 하는 대량 요청, 디렉터리 · 비밀번호 무작위 대입 |
| | 자동 스캐너를 오래 돌리기 |

문제를 풀 때 필요한 만큼의 요청은 괜찮습니다. 서버가 느려질 정도면 멈춥니다.

### 2-3. 공용 서버 매너

모든 참가자가 같은 서버를 씁니다. 한 사람이 망가뜨리면 모두가 못 풉니다.

- 문제에서 주어진 계정의 비밀번호를 바꾸거나 다른 참가자의 데이터를 지우지 않습니다.
- 서버에서 얻은 셸로 파일을 지우거나 프로세스를 끄지 않습니다.
- 다른 참가자가 볼 수 있는 곳(원서, 자기소개 등)에 플래그나 풀이를 남기지 않습니다.
- 플래그와 풀이를 다른 팀과 공유하지 않습니다.

문제가 이상하게 동작하면 운영진에게 알립니다. 운영진이 문제를 재시작하면 그 문제의 데이터가 처음 상태로 돌아갑니다.

### 2-4. 소스와 diff

소스는 공개되어 있어 읽어도 됩니다.
다만 원본 `app/` 과 문제 폴더를 `diff`, `git diff`, IDE 파일 비교로 맞대어 보지 않습니다.
바뀐 줄이 곧 답이 됩니다.

### 2-5. AI 는 공부 도구로만 씁니다

| 허용 | 금지 |
|---|---|
| 개념 설명 (예: "세션 쿠키가 뭐야") | 문제 소스를 통째로 넣고 취약점이나 풀이를 묻기 |
| 내가 고른 코드 일부의 동작 설명 | AI 가 찾아 준 답을 그대로 따라 하기 |
| 요청 보내는 법, 스크립트 문법 | |

### 2-6. 힌트는 한 단계씩 엽니다

막혔을 때 운영진에게 요청합니다.

1. 취약점 분류
2. 취약한 화면
3. 취약한 파일

### 2-7. 라이트업

대회가 끝나면 푼 문제마다 라이트업을 제출합니다. 양식은 `solution/` 의 풀이 양식과 같습니다.
