# medium-04 — 서류 대조

|  |  |
|---|---|
| 난이도 | Medium |
| 분류 | Web |
| 출제 | A조 |
| 접속 | http://<출제조IP>:8009 |
| 플래그 형식 | `GlassHouse{...}` |

## 설명

서류 위조 사건 이후 규정이 바뀌었습니다.
심사위원은 지원자가 올린 증빙서류를 **반드시 직접 열어 보고** 내부 보관함의 원본과 대조해야 합니다.
위조를 막기 위해 증빙서류는 PDF, JPG, PNG 만 받습니다.

원서를 제출한 뒤 **심사 요청** 버튼을 누르면 심사위원이 즉시 검토합니다.
심사 결과와 사유는 합격 조회 화면에서 확인할 수 있습니다.

접수팀 내부 폴더에 아직 발표되지 않은 추가 합격자 명단이 있다는 소문이 돕니다.

제공 계정: `applicant01 / test1234`

## 실행

```
cp .env.example .env     # 값을 모두 바꿉니다
docker-compose up --build -d
```

컨테이너는 두 개입니다.

| 서비스 | 역할 | 외부 공개 |
|---|---|---|
| `web` | 원서 접수 앱 | 8009 |
| `bot` | 심사위원 역할을 하는 헤드리스 브라우저 | 없음 (내부 전용) |

`bot` 은 `internal: true` 네트워크에만 붙어 있어 바깥 인터넷으로 나가지 못합니다.
심사 요청은 계정당 30초에 한 번, 대기열은 최대 10건입니다.

빌드 시 `bot` 이미지가 크롬을 받으므로 첫 빌드는 5분 이상 걸릴 수 있습니다.

## 출제자 확인 사항

- `.env` 의 `FLAG_XSS` 값이 앱이 켜질 때 `internal/waitlist.txt` 로 기록됩니다. 플래그를 바꾸면 앱을 다시 켜면 됩니다.
- `ADMIN_PASSWORD` 는 `web` 과 `bot` 이 함께 씁니다. 두 서비스 모두 같은 `.env` 를 읽습니다.
- 참가자가 `applicant01` 을 공유하면 서로의 원서와 심사 결과가 보입니다.
  대회에서는 계정을 나누거나 주기적으로 컨테이너를 재시작하십시오.
